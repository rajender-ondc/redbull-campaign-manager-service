The short version
We publish one fixed event schema and an events endpoint once — not per buyer app. Each buyer app wires it into its own systems, then posts events to us only for shoppers who arrived with an ondc_click_id: landing → product_view → add_to_cart → checkout → order_confirmed. Events carry IDs only, never a shopper's name, phone or address. An event without a click id is rejected. The landing page each campaign sends shoppers to is set on the campaign itself, not here.

05  Insights

Insights

Phase 1 runs a small, fixed rule set — the same rules for every campaign, affiliate and buyer app, so results compare like for like. Each gap is tested two ways: does it hold no matter which affiliate, and no matter which buyer app? The answer tells you whether the fix belongs at the deal, the platform, or the affiliate relationship — alongside two floors, on category-match and on ROI.

🏷️ Deal issue
Underperformance holds affiliate-agnostic — true across every affiliate on a campaign. The deal itself isn't landing, not any one partner's audience.
👥 Audience issue
Performance is affiliate-specific — one affiliate converts, another doesn't, same deal. Points at audience-fit, not the offer.
🎨 Platform issue
An affiliate's results shift by buyer app even with the same audience — pointing at that buyer app's landing/checkout experience, not the affiliate.
