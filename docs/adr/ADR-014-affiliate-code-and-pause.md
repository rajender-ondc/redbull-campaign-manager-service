# ADR-014: Affiliate code, defaults and pause rules

- **Status:** Accepted, 14 Oct 2026
- **Service:** S1 Configuration & Registry
- **Resolves:** C-S1-08 (the affiliate entity and its contract window). Also settles the affiliate part of C-S1-07 (link format and immutability).

## Context

An **affiliate** is a traffic partner network such as CashKaro, Admitad or Wishlink.
- It spreads our tracking links through its own publishers.
- It adds its own `aff_click_id` and `sub_id` to every tap.
- It is paid commission on attributed orders.

What the sources say:
- **PRD v1.2** defines no affiliate entity. It only needs a commission rate for each affiliate on a campaign (S1-03), and an affiliate contract window that governs the affiliate's reports (S3-13, S4-22).
- **Prototype v3:**
  - The form holds a name, an optional contact email, a default commission rate (required, default 6%) and a contract window (default 14 days).
  - **Pause** makes an affiliate "no longer selectable for new campaigns"; **Resume** makes it selectable again.
  - The Affiliates page filters by status and searches by name.
- **The team's data model** has a unique `code`, the four fields above, and a status of `active` or `paused`.

Every tracking link contains the affiliate's code; the PRD's example is `go.ondc.org/c/CAMP-2026-0089-CK`. Affiliates and their publishers paste these links into WhatsApp groups, Telegram channels and blogs, and a link that has been shared can't be called back.

## Decision

### Fields

| Field | Rules |
|---|---|
| `id` | UUID generated by the server |
| `code` | Generated by the server when the affiliate is created; never changes (see below) |
| `name` | Required, trimmed, 2–100 characters, unique ignoring letter case (409 `AFFILIATE_NAME_TAKEN`) |
| `contactEmail` | Optional (`null`); stored trimmed and lowercase; a valid email of at most 254 characters. It prefills recipients when Marketing sends a report (S4-23) |
| `defaultCommissionRatePercent` | Required; above 0, at most 100, up to 2 decimals |
| `defaultContractWindowDays` | A whole number from 1 to 60; 14 when omitted (as in the prototype) |
| `status` | `active` (always at creation) or `paused` |
| `currentVersionNo`, `createdAt`, `updatedAt` | As for every S1 resource (ADR-011) |

**The two defaults prefill campaigns.** When an affiliate is added to a campaign, the campaign copies the commission rate and contract window into its own `campaigns.affiliates[]` entry (the campaigns task). Changing a default later never changes existing campaigns.

### The code

**Generated, never typed.** Users never enter a code, just as they never enter an id (ADR-011).

**Format:** 2 lowercase letters followed by 4 characters, for example `ckB7XQ`.
- **The prefix** comes from the name.
  - The name is split into words at spaces, punctuation, digits and capitals inside a word: "CashKaro" becomes Cash + Karo.
  - With two or more words, the prefix is the first letters of the first two words: CashKaro → `ck`, Amazon Associates → `aa`.
  - With one word, it's the word's first two letters: Admitad → `ad`, Wishlink → `wi`. A one-letter word is padded with `x`.
  - If the name has no Latin letters at all, the prefix is `af`.
- **The suffix** is 4 characters from `BCDFGHJKMNPQRSTVWXZ23456789`.
  - There are no vowels, so a public link can never spell a word.
  - There are no look-alikes (0/O, 1/I/L).
  - Each character is picked by Node's secure `crypto.randomInt`, which gives 531,441 codes per prefix.

**Unique ignoring letter case,** enforced by a unique index with collation. If a freshly generated code is already taken, another one is generated, up to 5 tries.

**The code never changes, not even when the affiliate is renamed** (team decision, 14 Oct 2026).
- **Why:**
  - By the time an affiliate is renamed, links containing its code are in every campaign it runs on, and its publishers have already posted them.
  - A new code would either break all those links or leave one affiliate with two codes, which is "a huge mess" for Marketing, the affiliate and its publishers.
  - The name is a label for people; the code is the affiliate's identity inside links.
- **How it's enforced:**
  - A `code` in a POST is rejected ("code is generated by the server.") and so is one in a PATCH ("code cannot be changed.").
  - Mongoose's `immutable` option guards the field as well.
- **Consequence:** after a rename, the prefix may no longer match the name. For example, CashKaro renamed "EarnKaro Partners" keeps `ckB7XQ`. That's expected, because the prefix is only a readable hint.

### Pause and resume

- **How to change it:** `PATCH /api/v1/affiliates/{id}` with `{"status": "paused"}` or `{"status": "active"}`. It can be sent alone or with other changes, and an optional `If-Match` returns 412 if the affiliate has changed since.
- **What pausing does:**
  - A paused affiliate **can't be added to new campaigns**. The campaigns task enforces this for the wizard and for "Add to a campaign".
  - Campaigns it is already on keep running, and their links keep working. Stopping an affiliate on one live campaign is a separate, per-campaign status in `campaigns.affiliates[]`.
  - A paused affiliate is still listed, still editable, and can still be deleted if no campaign uses it.

### Delete

- A hard delete is allowed only while no campaign uses the affiliate (`campaigns.affiliates[].affiliateId`). Otherwise the answer is 409 `AFFILIATE_IN_USE`.
- Pausing is how an affiliate that has history is retired.

### List

- The list is sorted by name.
- `search` matches text anywhere in the name, the same convention as channels (ADR-010 §2).
- `status` limits it to `active` or `paused` affiliates. The campaign wizard asks for `status=active`.

## Alternatives considered

| Option | Why not |
|---|---|
| A code typed in by users | Users would have to invent codes and keep them unique. The team rejected typed codes for categories too |
| **A new code when the affiliate is renamed** | **Rejected (team decision): every link already issued with the old code would break or need reissuing** |
| A code made from the whole name, as the prototype's links do | It changes on rename, it's long, and similar names collide |
| Sequential codes (`ck01`, `ck02`) | They need a shared counter and reveal how many affiliates exist |
| Any letters and digits in the suffix | Codes could contain look-alikes (O/0, I/1) and spell words in public links |
| Separate `…/pause` and `…/resume` endpoints | Verbs in URLs. The status is a field, changed like any other (REST guidelines, ADR-010) |
| Multiple contact emails | The prototype and the data model have one. Report recipients are chosen at send time anyway (S4-23) |

## Consequences and known gaps

- **Matching links in any case.** Because codes are unique ignoring letter case, the link router (S2) can match a code typed in any case.
- **Collisions are rare.** With 531,441 codes per prefix a clash is unlikely. After 5 clashes in a row the create fails with a 500, which is logged, instead of looping.
- **Monthly targets** (C-S1-18) aren't affiliate fields.
  - The PRD's daily view (S4-07) needs month-to-date pacing against a target, but prototype v3 marks pacing as Phase 2.
  - A target is a separate affiliate × month record, left for a later task.
- **Rules for the campaigns task:**
  - only active affiliates can be added;
  - the default rate and window are copied into the campaign;
  - an affiliate paused while a campaign that adds it is being saved needs a transaction (a replica set).
- **The "in use" check covers current campaigns only.** The versioning task must also check stored campaign versions.
